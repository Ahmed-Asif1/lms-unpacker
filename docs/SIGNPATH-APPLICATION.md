## Description

LMS Unpacker is an independent, MIT-licensed utility that helps students and other users
turn ZIP downloads into usable local files. It can extract archives as they are, flatten
unnecessary folders, or organize course materials using user-defined courses and syllabus
rules. A Windows desktop interface and independent command-line editions provide previews,
conflict handling and reversible organization of existing documents. File processing is
local, without accounts, telemetry or uploading course materials.

## Reputation

LMS Unpacker is an early-stage, independently maintained open-source project. We do not
yet have substantial adoption statistics, independent media coverage or a third-party
security audit. Public evidence currently consists of the source and commit history at
https://github.com/Ahmed-Asif1/lms-unpacker, automated Windows/Linux checks and release
builds at https://github.com/Ahmed-Asif1/lms-unpacker/actions, and downloadable artifacts
with checksums and GitHub build attestations at
https://github.com/Ahmed-Asif1/lms-unpacker/releases. The source is also mirrored at
https://gitlab.com/ahmed007asif/lms-unpacker. These demonstrate development and build
provenance; they do not establish widespread use or independent endorsement.

## Before submitting

- Confirm that the download page leads to a published release. A draft is not a public download.
- The download page truthfully says an application is being prepared and builds are unsigned.
  The form requests provider attribution, but actual SignPath use must only be claimed after
  approval and verified integration. Explain this status if the application reviewer asks.
- The project name must be identifiable in search. Search indexing and name uniqueness are
  not guaranteed by publishing a repository; verify search visibility before asserting it.
- Confirm MFA for every repository and signing team member. Repository access does not
  allow this project to verify personal account MFA settings.
- Review the [signing policy](SIGNING.md). External contributions need review and future
  signing requests require manual approval. No automatic signing integration is claimed yet.
- Executable signing requires verifiable project reputation under the Foundation's terms.
  An honest application can still be declined or deferred while the project is new.
- Read the Code of Conduct and privacy terms yourself. Accept required agreements only
  if you agree. Marketing consent is optional; leave it unchecked unless you want it.
  Complete reCAPTCHA and submit personally.
